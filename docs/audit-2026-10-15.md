## Input for the GCS / Cloud CDN / Cloud Armor phase (from the map slice)

1. GCS is only the S3 client with `base_url = https://storage.googleapis.com` and HMAC keys; no GCS code.
2. SDK 3.369.22 defaults to flexible checksums (`request_checksum_calculation = when_supported`); the plugin
   never sets `when_required` — a known source of failures against S3-compatible stores (unverified on GCS).
3. Canned ACL header always sent through `ObjectUploader`; fails on uniform bucket-level access; several ACL
   values offered are AWS-only.
4. Tagging falsely supported (A10).
5. Signed-URL provider hard-coded `s3 | cf`; `generate_presigned_url_s3()` and `get_nice_filename()` are private;
   `proxy_range_request` always signs with S3 and disables TLS verification (A5). Cloud CDN signing (HMAC-SHA1,
   URL prefix or cookie) does not exist.
6. Credentials: HMAC or the AWS provider chain only — no GCE/GKE/Cloud Run metadata-server path.
7. No `Cache-Control` / `Content-Disposition` metadata on upload.
8. No reverse-proxy or client-IP handling in the plugin (core's `reverseproxy` / `sslproxy` decide).
9. Unavoidable upstream-file edits for a new provider: `manager::get_available_fs_list()`, the `signingmethod`
   select in `settings.php`, `tool_objectfs_status_checks()` for new checks.
